# 非功能需求（NFR）

> **版本**：v0.1
> **上游**：`01-prd.md` §5
> **原则**：每条 NFR 必须有**可测量的指标**、**测量方法**、**不达标的处置**。没有测量方法的需求不是需求，是愿望。

---

## 1. 容量

| 指标 | Wave 1 | Wave 3 | 测量方法 |
|---|---|---|---|
| 设备数 / 实例 | 200 | 1000 | 压测：虚拟设备批量实例化 |
| 点位数 / 实例 | 10,000 | 50,000 | 同上 |
| 点位变化率 | 5,000 samples/s | 20,000 samples/s | 虚拟设备高频变化 |
| Outbox 积压 | 1,000,000 条 / 256 MB | 同 | 断网注入 |
| SSE 并发客户端 | 50 | 200 | 连接数压测 |
| 历史保留（边缘） | 7 天（Wave 2） | 30 天 | 磁盘水位 |

**容量预算表（单设备）**：

| 资源 | 预算 | 说明 |
|---|---|---|
| 内存 | 60 KB / 设备 + 200 B / 点位 | 1000 设备 10 万点 ≈ 80 MB |
| goroutine | ≤ 1 个在飞任务 / 设备 + 固定 worker | 不随设备数线性增长 |
| 文件描述符 | 1 / TCP 通道 + 1 / 串口 | 连接复用 |

## 2. 性能

| 指标 | 目标 | 测量条件 | 处置 |
|---|---|---|---|
| 采集周期下限 | 100 ms | 单设备 50 点，批量合并 | 低于此值拒绝配置 |
| 单次采集 P95 | ≤ 周期 × 0.5 | 局域网，50 点 | 记录慢设备 |
| 写命令 P95 | ≤ 300 ms | 读满载（200 设备） | 调大通道并发或查网络 |
| REST 单点读 P95 | ≤ 20 ms | 10,000 点快照 | 优化索引 |
| REST 列表 P95 | ≤ 100 ms | 1000 条 + 分页 | 加索引/降字段 |
| SSE 端到端 P95 | ≤ 500 ms | 1000 点/s | 检查背压 |
| 冷启动到 ready | ≤ 3 s | 1000 点配置 | 延迟加载 |
| 配置应用 | ≤ 2 s | 改 1 台设备 | 差异计算优化 |
| 配置回滚 | ≤ 30 s | 全量配置 | 快照加载优化 |
| 内存增长（72h） | ≤ 5% | 稳定负载 | 查泄漏 |

**基准测试要求**：每个驱动必须有 `BenchmarkRead`，CI 记录基线；回归超过 20% 告警。

## 3. 可靠性

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 连续运行 | 30 天无重启 | 浸泡测试（72h 加速 + 现场） |
| 可用性（单实例） | 99.5% / 月 | 健康检查统计 |
| 断网补发 | 24h 数据不丢 | 断网 24h 后核对 |
| 配置回滚成功率 | 100% | 注入 20 类非法配置 |
| 单设备故障隔离 | 不影响其他设备 | 故障注入 |
| 采集假死检测 | ≤ 60 s | 看门狗注入 |
| 优雅退出 | ≤ 10 s | SIGTERM 测试 |
| 掉电配置完整性 | 100% | 写入过程断电模拟 |

### 3.1 故障注入矩阵（必须全部通过）

| 故障 | 注入方式 | 期望行为 |
|---|---|---|
| 连接拒绝 | 关闭端口 | `degraded`，退避重连，不崩溃 |
| 连接中断 | 中途 RST | `comm_error`，重连，代次递增 |
| 响应超时 | 延迟 2×timeout | `timeout`，熔断计数 |
| 半包 | 只发一半 | 传输层等待补全或超时 |
| 错 CRC | 翻转字节 | `protocol` 错误，不重试 |
| 异常码 | 返回 0x02 | `address_error`，**不熔断** |
| 部分响应 | 少返回 1 个寄存器 | `bad` + 明确日志 |
| 慢响应 | 逐次变慢 | 标记慢设备，不影响其他 |
| 磁盘满 | 写满数据目录 | 停历史、降级 Outbox、告警 |
| 时钟跳变 | ±1h | 采集不中断、无重复 |
| 进程假死 | SIGSTOP 60s | 外部 supervisor 重启 |
| Broker 断线 | 停 MQTT | Outbox 积压，恢复后补发 |

## 4. 安全

| 项 | 要求 | 验证 |
|---|---|---|
| 认证 | 默认开启；无凭据时为 open 模式并打 `auth_open_mode` WARN（不生成默认口令） | 启动横幅 + 日志核对 |
| 口令/Token | ≥ 16 字符，禁用常见弱口令表，禁止空白字符 | 配置加载时校验 |
| 凭据存储 | Token 先 SHA-256 再定长比较；配置可只存 `tokenSha256`（不可逆），明文不落盘 | 配置文件扫描 |
| 凭据热更新 | `server.users` 变更 apply 后下一条请求即按新表判定；删掉的用户立刻 401 | 端到端测试 |
| 传输 | API 默认 TLS（自签可） | 扫描 |
| 授权 | 最小权限；写操作需显式权限 | 越权测试 |
| 审计 | 认证/授权失败/配置/写入/命令/确认；写失败不阻断业务但计入 `uic_audit_write_errors_total` | 日志核对 + `/audit/verify` |
| 依赖 | 仅 MIT/Apache/BSD/ISC | CI 扫描 |
| SBOM | 每次发布生成 | 构建产物 |
| 帧日志 | 只打印前 32 字节 + 长度 | 代码审查 |
| 诊断包 | 脱敏（口令、Token、私钥） | 自动测试 |

**红线**（任一不满足即不可发布）：

1. 存在默认口令；
2. 配置文件含明文口令；
3. 未认证即可写点位；
4. 依赖含 GPL/AGPL；
5. 诊断包含凭据。

## 7. 可观测性

| 项 | 要求 |
|---|---|
| 指标 | 每设备/通道/协议/北向端点均有计数器与直方图 |
| 日志 | JSON 行；字段包含 `ts/level/msg/device/channel/protocol` |
| 日志级别 | `debug/info/warn/error`；可按设备动态调整 |
| 日志轮转 | 单文件 100 MB，保留 5 份 |
| 追踪 | Wave 3（OpenTelemetry，可选） |
| 健康 | 三级（live/ready/business）；business 级含采集中枢活性 `scheduler.verdict`（healthy/stalled/unknown）与 `status="stalled"` |
| 看门狗 | 主动检测调度器 tick 停摆（默认 15s 无 tick 判 stalled），边沿触发记 `uic_scheduler_stalled_total` 并写日志；`/healthz` 与 `/readyz` 契约不变 |
| 心跳文件 | `<dataDir>/heartbeat.json` 原子写（tmp+rename），含 `tsMs` 与 `scheduler.verdict`，供不访问 HTTP 的 supervisor 区分「进程死」与「活着但卡死」 |
| 诊断 | 一键诊断包 |

**指标预算**：单实例序列数 ≤ 20,000（1000 设备 × 20 序列），避免 Prometheus 基数爆炸。高基数标签（点位 ID、报警 ID 等**路径参数**）**禁止**作为指标标签，只进日志。HTTP 层在 `metricPath` 把路径归一化成占位符（`/api/v1/points/:device/:point`、`/api/v1/alarms/:id`…）；归一化必须覆盖**每一类前缀下的任意子路径，包括返回 404 的那一段**——否则不存在的 URL 就成了绕过归一化的缺口，反复请求不同 id 即可把序列数撑爆。

## 12. 结论

1. **NFR 的价值在于「可测量」。** 「高性能」「高可靠」不是需求；「1000 点 P95 ≤ 500ms、72h 内存增长 ≤ 5%」才是。

2. **故障注入矩阵是可靠性的真正验收标准。** 12 类故障覆盖了现场 90% 的异常形态；能全部通过，才谈得上「无人值守」。

3. **安全红线的五条必须做成不可配置的硬约束。** 一旦允许「为了演示方便先关掉认证」，它就会永远关着——这是 38 个方案里反复出现的路径。
