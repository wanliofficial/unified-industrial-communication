# 分析卷写作约定（内部规范）

## 1. 脱敏规则（强制）

本卷所有文档**不得出现**任何被分析对象的名称、仓库地址、作者名、公司名、产品商标、模块命名前缀。包括但不限于：

- 项目名、组织名、仓库名、包名前缀、命名空间前缀、类名前缀（若该前缀本身即项目标识）。
- 界面截图中的产品名、关于页中的版权信息、许可证头中的版权人。
- 任何可被搜索引擎直接反查到来源的唯一短语（例如项目自述里的口号、独特的功能命名）。

允许出现的内容：

- 工业协议与标准名称：Modbus、S7、S7comm、OPC UA、OPC DA、IEC 60870-5-101/104、IEC 61850、DNP3、BACnet、MQTT、Sparkplug B、SECS/GEM、EtherNet/IP、CIP、PROFINET、PROFIBUS、CANopen、DL/T 645、CJ/T 188、MTConnect、FOCAS、ADS、KNX、CoAP、SNMP、Modbus RTU/TCP、Host Link、FINS、MC 协议、Mewtocol、CC-Link 等。
- 通用技术名词：Netty、Spring Boot、WinForms、WPF、Avalonia、Blazor、Electron、Vue、React、SQLite、Redis、TDengine、InfluxDB、Docker、Kubernetes、gRPC、WebSocket、SSE 等。
- 编程语言与运行时名称。
- 抽象后的架构名词：驱动、采集器、通道、点位、标签、设备影子、北向、南向、时间片、批读计划等。

替代写法：

| 需要表达 | 写法 |
|---|---|
| 某个被分析对象 | `PA-xx` + “该方案” |
| 被分析对象的类名 | 改写为角色名，如“设备通信基类”“统一返回结果类型” |
| 被分析对象的目录名 | 改写为“驱动目录”“协议子模块” |
| 被分析对象的口号/宣传语 | 不复述，改写为功能陈述 |

## 2. 事实与推断分离（强制）

- 事实必须来自代码、配置、文档或可运行行为，写作时给出**证据形态**（如“在 `XxxManager` 中存在按设备 ID 缓存连接池的字段”），但不粘贴大段原始代码，不复制原始注释。
- 推断必须显式标注：`（推断）`。推断用于解释设计动机、评估成熟度、判断未完成部分。
- 不确定的数字不要编造；写“约”“未见明确实现”“文档声称 N 种，代码中可核实的为 M 种”。

## 3. 结构要求

每份文档必须包含且仅包含以下一级章节（顺序固定）：

1. 定位与问题域
2. 功能分析
3. 架构分析
4. 需求分析
5. 可借鉴与应规避
6. 结论

二级章节按 `_TEMPLATE.md` 执行，可按方案特点增删，但不得省略“功能分析 / 架构分析 / 需求分析”三章。

## 4. 深度要求

- 功能分析：功能域 → 功能点 → 实现方式 → 完成度，四层都要有。协议清单要给出“协议名 / 角色（主站·从站·双角色）/ 传输（TCP·串口·UDP）/ 代码位置或模块 / 备注”。
- 架构分析：必须画出模块关系（Mermaid 或 ASCII），必须指出**关键抽象接口**及其职责边界，必须说明**并发模型**（线程/协程/事件循环、锁粒度、连接复用、背压）与**故障恢复**（重连、退避、熔断、缓存补发）。
- 需求分析：从“谁在什么现场、要解决什么”出发，区分显性需求与隐性需求；隐性需求通常包括：断网续传、时钟漂移、点位变更不停机、地址越界保护、字节序与字序、批量读优化、诊断可观测性、许可与合规。
- 结论：给出六维评分表（协议广度、架构可演进性、跨平台能力、可运维性、工程质量、许可与合规风险），每维 1–5 分并给一句理由；给出三条关键结论。

## 5. 篇幅

- A 级（重点方案，PA-01/03/05/06/07/08/09/10/12/13/16/17/23/34/37）：220–380 行。
- B 级（其余）：140–240 行。
- 不写填充段落；每一段都要携带信息量。表格优先于长段落。

## 6. 术语统一

| 术语 | 含义 |
|---|---|
| 南向 | 面向设备/PLC 的采集侧 |
| 北向 | 面向 SCADA/MES/云平台/数据库的输出侧 |
| 通道 | 一条物理或逻辑链路（TCP 连接、串口、UDP 会话） |
| 设备 | 一个可寻址的从站/站点，含协议与连接参数 |
| 点位/标签 | 设备内的一个可读写数据项，含地址、类型、工程单位、缩放 |
| 批读计划 | 把离散点位合并为若干连续读请求的规划结果 |
| 时间片 | 把设备轮询分散到固定时间槽以避免同时打满网络 |
| 质量码 | 描述数值可信度的枚举（Good/Bad/Uncertain/Stale/Timeout 等） |
| 设备影子 | 设备最新状态与期望状态的持久化副本 |
| Outbox | 待上报消息的持久化队列，保证至少一次投递 |
